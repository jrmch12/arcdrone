
Good target-setting question. With your numbers, a useful way is to choose by student total updates relative to teacher.

Teacher total updates: ~7000
Student total updates:
[
\text{student_updates} \approx \text{teacher_updates} \cdot \frac{\text{align_updates_per_trigger}}{\text{align_freq} \cdot \text{num_updates_per_batch}}
]
With your num_updates_per_batch=16, ratio is controlled by align_updates_per_trigger / (16 * align_freq).
Reasonable presets

Conservative: align_updates_per_trigger=2, align_freq=4, align_batch_per_device=256
Student updates ≈ 7000 * 2/(16*4) = 219
Balanced (recommended start): align_updates_per_trigger=4, align_freq=2, align_batch_per_device=512
Student updates ≈ 7000 * 4/(16*2) = 875
Aggressive IL: align_updates_per_trigger=8, align_freq=1, align_batch_per_device=1024
Student updates ≈ 7000 * 8/16 = 3500
Important caveat: with rollout env steps ≈ 131k, you only have about 6e6/131k ≈ 46 training steps total. So if this exact setup is used, keep align_freq=1 (or maybe 2), otherwise alignment triggers become too sparse.

If you keep the new ratio flag (align_batch_ratio_per_device) instead of absolute batch:

256 ↔ ratio ~0.002
512 ↔ ratio ~0.004
1024 ↔ ratio ~0.008

Perfect — here’s the exact fix I’d implement so align_freq means:

teacher optimizer updates / student optimizer updates (true ratio)
1) In train.py, replace the trigger math
Use cumulative optimizer updates, not training-step count:



# teacher training steps before/after this call
prev_teacher_steps = training_state.env_steps // env_step_per_training_step
new_env_steps = training_state.env_steps + env_step_per_training_step
new_teacher_steps = new_env_steps // env_step_per_training_step

# cumulative TEACHER optimizer updates
prev_teacher_opt_updates = prev_teacher_steps * num_updates_per_batch
new_teacher_opt_updates = new_teacher_steps * num_updates_per_batch

# exact STUDENT updates due this step from ratio
# align_freq := teacher_updates / student_update
student_updates_due = (
    new_teacher_opt_updates // align_freq
    - prev_teacher_opt_updates // align_freq
)
do_align = student_updates_due > 0

Then inside _align_step, call alignment with student_updates_due (not fixed trigger count).

2) In align.py, make update count dynamic
Change signature:


def align(..., align_updates_per_call, *, sitt_network, optimizer):

Replace fixed lax.scan(... length=align_updates_per_trigger) with:

(student_dec_params, proxy_dec_params, opt_state) = jax.lax.fori_loop(
    0,
    align_updates_per_call,
    lambda _, carry: step(carry, None)[0],
    (student_dec_params, proxy_dec_params, opt_state),
)

This lets each training step run exactly however many student updates are due by the ratio.

3) Keep align_updates_per_trigger as optional chunking (or remove it)
If you keep it, redefine it as chunk size only (not ratio).
If you want simplest semantics, remove it and use only align_freq.

With this, your intuition is correct: if align_freq=4, student updates track roughly teacher_updates / 4 over time (exact by floor on cumulative counts).
